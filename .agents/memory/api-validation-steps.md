---
name: API validation steps
description: How the api-server integration test scripts are registered as validation steps, why each run builds into a private directory, and which script contracts they rely on.
---

Registered API-server validation steps (shop-isolation, customer-balances, registration-gate, stage-locks, portal-repair-isolation, public-requests, chat-blocks, chat-reports, push-delivery, chat-relay-purge-e2e, …) each run:
`cd artifacts/api-server && flock /tmp/api-server-tests.lock node scripts/run-isolated.mjs scripts/<script>.mjs`

**Why:** validation commands run concurrently with each other, the api-server dev workflow, and `workspace-build`, and all of those rewrite `artifacts/api-server/dist/`. A test that had just built into `dist/` would find `dist/index.mjs` gone when it spawned the server (`Cannot find module .../dist/index.mjs` right after a successful build). Serialising builds with flock is not enough because builds outside the test lock still clobber `dist/`. The fix is ownership, not locking: `run-isolated.mjs` builds into `tmp/isolated-builds/<run-id>/` (via `API_SERVER_OUT_DIR`, which build.mjs only accepts inside the artifact so externals still resolve from its node_modules) and hands the entry to the script through `API_SERVER_ENTRY`. The tests lock remains only to keep the suites' fixed ports and shared dev database from contending.

**Two registration shapes.** Scripts that *spawn* the built server go through `run-isolated.mjs` (above) — one validation step per script, and the `test-registration-guard` step fails completion for any `scripts/test-*.mjs` without one (`test-customer-khata.mjs` and `test-dealer-detection.mjs` had silently dropped out of `.replit`; the latter rotted for months — a non-existent `staff` role and a retired `DEALER_LINK_PRIVILEGED` rule — because nothing ran it). In-process vitest suites (`src/**/*.test.ts`: supertest against the imported app or direct lib calls, real dev database, providers stubbed via env/fetch) all run through ONE catch-all step, `api-vitest` = `cd artifacts/api-server && CI=1 flock /tmp/api-server-tests.lock flock /tmp/heavy-checks.lock npx vitest run` (api lock first, then the shared heavy-checks lock — same order as the relay e2e; `CI=1` keeps vitest off its interactive pty reporter) with no file list — `vitest.config.ts` `include` discovers every current and future file, so adding a suite needs no registration. They never touch `dist/`, and the validation harness environment already carries `DATABASE_URL` and the secrets, so no isolated build or extra env wiring is needed (28 files / 420 tests ≈ 80 s in one process, `fileParallelism: false`). Do not go back to per-domain steps with explicit file lists (the earlier `chat-relay` / `chat-routes` steps): a file list is exactly how 22 of 28 suites silently stopped running at completion and the chat message-alert title assertion drifted red, and a second vitest step only re-runs the same files under the shared lock. The step must keep the tests flock even though vitest needs no port — the suites share the dev database with the spawn-server scripts and each other's fixtures.

**Supertest goes through an alias.** `vitest.config.ts` aliases the bare `supertest` specifier to `src/test-support/supertest.ts`, which hands supertest one shared, already-listening server per app (fixed port 5799, ephemeral fallback when taken) instead of letting it `listen(0)` a fresh server for every `request(app)` call. The workspace supervisor keeps memory for every newly seen listening port (see validation-run-starvation.md), and ~500 ephemeral ports per run crashed it. Keep importing `supertest` by its bare name in tests, never by path, and never `app.listen(0)` per request in a helper; keep the fixed port clear of the spawn scripts' ports (5641–5694).

**How to apply:** any new api-server integration script must read `process.env.API_SERVER_ENTRY ?? "./dist/index.mjs"` for its spawn target and be registered through `run-isolated.mjs`, never `pnpm run build && node scripts/...`. Scripts resolve relative to cwd, so they must run from `artifacts/api-server`. Test-script API contracts to honor: delivery requires the testing gate (`POST /repairs/:id/testing {confirm:true}`) unless already `ready`; advance only via `POST /repairs/:id/payments` (methods are capitalized: "Cash", "UPI"…), overpayment → 400 OVERPAYMENT; registration is dealer/staff-only with no admin access code.

Related browser-suite lesson: Radix toast text is duplicated into a visually hidden announcer portaled outside the `Notifications` region for a timing-dependent moment, so unscoped `getByText(toast copy)` intermittently hits two elements. Scope toast assertions to `page.getByRole("region", { name: /notifications/i })`.

**Cross-client end-to-end scripts (relay purge pattern):** when a script must exercise a server *library* directly (not through HTTP), do not copy its logic — put a tiny re-export entry under `scripts/lib/*.ts` and esbuild it with `bundleOptions` exported from `build.mjs` into the run's private directory; `build.mjs` therefore must stay import-safe (it only builds when invoked directly). Third-party providers (Matrix, Expo push) are replaced by a local HTTP stub via env overrides on the spawned server, never called for real. Browser legs build the static web apps with `vite build --outDir <private dir> --emptyOutDir` (never the shared `dist/public`, never a production `VITE_API_URL`; set `VITE_API_FALLBACK_URL=""`) and serve them with `vite preview --outDir … --strictPort`; the app's same-origin `/api` calls are forwarded to the test API with Playwright `route.fetch({ url })` + `route.fulfill({ response })`, which needs no CORS/ALLOWED_ORIGINS change. `playwright-core` is borrowed from update-admin via createRequire; Chromium is at `/repl/tools/bin/chromium`. Operator state the script toggles (`app_settings` switch, last-run summary, a fixture published critical `app_updates` row) must be snapshotted and restored/deleted in a finally block and asserted in cleanup — the dev workflow API shares the same database and would otherwise advertise the fixture release. Scripts that import the bundled server modules must `process.exit` at the end (pino worker + pg pool keep the loop alive).
