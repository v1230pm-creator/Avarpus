BUILD: VMC Electronics ERP – Central Server-Side OTA App Update Management System

IMPORTANT:
The Android application already has an App Update screen.
Now build the complete SERVER-SIDE update management system that will control and distribute application updates to all installed VMC Electronics ERP applications.

Do NOT rebuild the existing Android update UI unless an API integration is required.

First inspect the existing VMC Electronics ERP project architecture, backend, database, authentication, admin panel, file storage and API structure.

Reuse the existing technology and coding conventions.
Do not introduce a new framework unnecessarily.

==================================================

==================================================
3. APK UPLOAD
==================================================

When an administrator uploads an APK:

1. Validate the uploaded file.
2. Verify that the file is actually an Android APK.
3. Verify the Android application package/application ID.
4. Verify that it belongs to the VMC Electronics ERP application.
5. Extract APK metadata where technically possible.
6. Calculate APK file size automatically.
7. Generate SHA-256 checksum automatically.
8. Store the APK securely.
9. Store the APK metadata in the database.

Do NOT trust the file name or extension alone.

Reject invalid APK files.

Display upload progress.

Show:

- File name
- File size
- Upload status
- SHA-256 checksum
- Validation status

==================================================
4. APK STORAGE
==================================================

Create a secure APK storage structure.

Example:

/app-updates/
    /android/
        /1.0.0/
        /1.5.0/
        /2.0.0/
        /2.1.0/

Do not expose the physical storage path directly.

Use secure download URLs or controlled API endpoints.

Unpublished APK files must not be publicly downloadable.

If the existing project already has cloud/object storage, reuse it.

Do not store large APK binaries directly inside the database.

Store only the file reference/path/URL and metadata in the database.

7. VERSION VALIDATION
==================================================

Use BUILD NUMBER as the primary version comparison value.

Example:

Installed:

Version: 2.0.0
Build: 200

Version: 2.1.0
Build: 210

Do not rely only on the visible version string.

Prevent an administrator from publishing a build number lower than the currently published build unless an explicit administrator override is implemented.

Show a warning when attempting to publish an invalid/older build.

  "version": "2.1.0",

14. VERSION CHECK LOGIC
==================================================

The Android application will send its current information.

Example:

GET /api/app-updates/latest?platform=android&buildNumber=200

The server must compare:

Client Build Number
vs
Latest Published Build Number

If:

clientBuild >= latestBuild

return:

updateAvailable: false

If:

clientBuild < latestBuild

return:

updateAvailable: true

Never expose unpublished updates to the application.

==================================================
15. APK DOWNLOAD ENDPOINT
==================================================

Create a secure APK download mechanism.

Example:

GET /api/app-updates/download/:updateId

Requirements:

- HTTPS only
- Verify that update is published
- Verify that APK exists
- Return/download the correct APK
- Support large file downloads efficiently
- Support HTTP range requests/resume where technically possible
- Do not expose internal storage paths
- Prevent access to draft/unpublished APKs

==================================================
16. APK SECURITY
==================================================

For every APK:

- Generate SHA-256 checksum.
- Store checksum.
- Return checksum through API.
- Verify APK package/application ID.
- Verify APK exists before publishing.
- Reject corrupted uploads.
- Use HTTPS.
- Prevent unauthorized APK replacement.
- Protect upload endpoints using admin authentication.
- Protect publish/unpublish endpoints using admin authorization.

The Android application will verify the SHA-256 checksum before installation.

26. VERY IMPORTANT BUSINESS RULE
==================================================

There must be NO Play Store dependency.

The server must act as the central source of truth for VMC Electronics ERP Android application updates.

- Do not automatically install updates.
